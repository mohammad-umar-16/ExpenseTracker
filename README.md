# Expense Tracker

A full-stack personal expense tracking application with AI-assisted expense entry, built with **React (Vite)** on the frontend and **FastAPI** on the backend. Track daily spending, scan receipts, get AI-generated spending insights, and stay on top of category budgets — all wrapped in a distinct ledger-book visual identity instead of the typical AI-dashboard look.

**Live app:** [expense-tracker-ochre-ten-98.vercel.app](https://expense-tracker-ochre-ten-98.vercel.app)

---

## Features

### Core
- Daily expense tracking with category tagging, notes, and a monthly calendar view
- Interactive charts — category breakdown (pie), daily spending trend (area chart)
- Search and filtering across all recorded expenses (title/note text, category, amount range, date range)
- Per-category monthly budgets with visual progress tracking and over-budget warnings
- Downloadable monthly PDF report
- Light/dark theme toggle with persistence

### AI-assisted
- **Quick Add** — natural-language expense entry (e.g. *"420 on swiggy dinner"*). A fast keyword matcher runs first; unrecognized text falls back to an LLM call, so most entries never need an API call at all.
- **Receipt photo scanning** — upload or photograph a receipt and have the total, merchant, and category extracted directly from the image via Gemini's multimodal input.
- **Spending insights** — short, factual monthly observations (e.g. *"You spent 22% more on Food this month"*), generated by comparing the current and previous month's data. Falls back to a deterministic, rule-based summary if no AI key is configured, so the feature never fully breaks.

### Security & reliability
- Authentication via **httpOnly cookies** (not `localStorage`) — the JWT is never exposed to client-side JavaScript, protecting against XSS token theft
- Login rate-limiting: account locks for 15 minutes after 5 failed attempts
- All expense/budget queries scoped to the authenticated user — verified in tests, not just assumed
- Automated backend test suite (pytest) covering auth, ownership isolation, search filters, and the parsing logic

## Architecture Notes

A few decisions worth calling out, since they weren't the "default" choice:

- **Cookies over `localStorage` for auth.** More secure against XSS, but requires care with cross-site cookie behavior. Since the frontend (Vercel) and backend (Render) are on different domains, browsers can treat the auth cookie as third-party and block it. This is solved with a **Vercel rewrite** (`vercel.json`) that proxies `/api/*` requests through the frontend's own domain — from the browser's perspective, all requests are same-origin, so the cookie is set as first-party.
- **Two-tier AI parsing, not AI-only.** Quick Add and Insights both try a free, instant, local method first (keyword matching / rule-based math) and only call the LLM when that's insufficient. This keeps the app fully functional with zero API cost for the common case, and avoids a hard dependency on a third-party API for core functionality.
- **`pool_pre_ping` and `pool_recycle` on the DB engine.** Serverless Postgres providers (Neon) can silently close idle connections. Without these settings, the app would intermittently throw `SSL connection has been closed unexpectedly` errors under low traffic.

## Local Setup

### Backend

```bash
cd backend
python -m venv venv
venv\Scripts\activate        # Windows
# source venv/bin/activate   # macOS/Linux

pip install -r requirements.txt
```

Create a `.env` file in `backend/` (see `.env.example` for the full list):

```env
DATABASE_URL=postgresql://user:pass@host:5432/dbname
SECRET_KEY=<a long random string>
ACCESS_TOKEN_EXPIRE_MINUTES=60
CORS_ORIGINS=http://localhost:5173
GEMINI_API_KEY=<optional — get one free at aistudio.google.com>
ENV=development                # relaxes cookie flags for local http testing
```

Run the server:

```bash
uvicorn main:app --reload
```

### Frontend

```bash
cd frontend
npm install
```

Create a `.env` file in `frontend/`:

```env
VITE_API_URL=http://localhost:8000
```

Run the dev server:

```bash
npm run dev
```

## Running Tests

```bash
cd backend
python -m pytest tests/ -v
```

Tests run against an isolated SQLite database (`test.db`, created and torn down automatically) — they never touch the production database. Coverage includes:

- Registration, duplicate-email rejection, login lockout after repeated failed attempts
- Expense ownership isolation (one user cannot view, edit, or delete another user's data)
- Search/filter correctness
- Budget upsert behavior (create vs. update, not duplicate)
- Keyword parser logic (category detection, amount extraction, overflow-to-note handling)

## Deployment Notes

- **Frontend (Vercel):** set `VITE_API_URL` to empty/blank in production — requests go through the `vercel.json` proxy rewrite instead of hitting the backend domain directly, which keeps the auth cookie first-party.
- **Backend (Render):** set `ENV` to anything other than `development` (or leave unset) so cookies get `Secure` + `SameSite=None`, required for the cross-site-but-proxied setup to work correctly in production.
- **Database:** any Postgres provider works; this project uses Neon specifically for its genuinely-free-forever tier (as opposed to Render's free Postgres, which expires after 30 days).
